# GoIM 在线更新发布

正式版本在「设置 → 关于」检查更新。Windows 当前用户 Setup 安装版、位于可写目录的 macOS 应用和通过 dpkg 安装且带更新助手的 Linux DEB 版支持应用内升级。MSI、Windows 便携版和 Linux tar.gz 提供官方下载。macOS 在线升级使用对应架构的 ZIP，首次安装可从 DMG 将 GoIM 拖入「应用程序」。

麒麟、统信 UOS 等 Debian 系发行版上，先手动安装一个带更新助手的 DEB。此后的稳定版本可在 GoIM 中下载，点击安装后通过桌面的系统授权。授权和软件包校验通过后，GoIM 自动退出，安装完成后以原用户重新打开。取消授权会保留当前窗口和已下载的包。缺少 pkexec 或更新助手时可直接下载 DEB。

1. 使用当前锁定版本的 Viva CLI `viva update-keygen -private <私钥文件> -public <公钥文件>` 创建 GoIM 专用密钥。私钥文件放在仓库之外。将 CLI 输出的 **Base64 公钥**设为仓库 Actions 变量 `GOIM_UPDATE_PUBLIC_KEY`；有权限的维护者将对应私钥设为 `goim-release` 环境的 secret `GOIM_UPDATE_PRIVATE_KEY`。保护该环境，只允许正式版本 tag 使用，并限制发布权限。
2. 推送新的 `v主.次.补丁` tag。确认发布构建通过六个平台的打包和校验，且 `GoIM-signed-update-feed` 产物生成。日常分支不会调用签名步骤；没有生产公钥时照常构建，但客户端不做在线检查。
3. 将 12 个包、Linux 文件选择器源码、`SHA256SUMS` 和 `GoIM-signed-update-feed` 的全部文件上传到同一 tag 的 Release 草稿。更新文件包括 `goim-update.json`、`goim-update.json.sig`、`goim-update.json.deb-amd64` 和 `goim-update.json.deb-arm64`。两个 DEB 描述文件使用同一发布密钥，签名绑定架构、版本、长度和 SHA-256。核对附件后再将草稿设为 Latest。
4. 用前一稳定版验证 Windows Setup、macOS 和 DEB 更新，确认重启后的版本、用户数据目录和截图工具。macOS 的发布检查还会解压在线更新所用 ZIP，校验应用标识、版本和嵌套代码签名。

没有签名、签名无法验证、清单地址不符合发布约定或软件包校验失败时，GoIM 不启动安装。失败可在「关于」重新检查或使用官网发布页；下载中断可继续。

## 安装前退出

应用内更新助手等待当前 GoIM 进程结束后才替换文件。Windows Setup 安装器也会检查主窗口和安装目录中的可执行文件是否仍被占用；发现运行实例时提示先从托盘退出，静默安装则返回失败，不再将运行文件改名后继续安装。独立 MSI 包在移除旧版本之前执行进程检查。

Linux `.deb` 在 `preinst` 阶段检查 `/usr/bin/GoIM` 是否仍在运行，若运行则中止安装并提示退出后通过系统安装器重试，不强制结束进程或要求重启系统。此检查随 0.1.14 及之后的安装包提供；旧安装器无法追溯修改。便携归档由用户在退出 GoIM 后完整解压替换。

## 自动检查周期

自动检查默认开启，保留用户明确关闭的设置。正式构建在启动时后台检查，此后每 6 小时检查一次；网络或更新源检查失败后，30 分钟后重试。重新开启开关会立即检查，不再受「已检查」或「检查失败」状态限制。关闭开关后停止后续自动检查，仍可手动检查。

检查、下载和安装不会并行启动重复检查；已有待安装的软件包时，自动检查不会覆盖它。退出程序会取消检查与调度。调度使用后台定时器，只在检查状态变化时唤醒界面，不通过重绘计时器轮询，也不会自动下载或安装。
