# 内网通适配进度

原版验收客户端为内网通 `3.4.3055`。普通互通从 GoIM 0.1.2 基线开始验收，本轮已用当前开发代码复跑原版可自动验证的场景。更新于 2026-11-18。“原版通过”仅指该行列出的范围。

| 功能 | 进度 | 现有证据与待补验收 |
| --- | --- | --- |
| 指定地址发现、资料握手 | 原版通过 | 沙箱和 VMware 中的 Windows 原版均建立控制连接；已有重复握手导致断线的回归用例。 |
| 局域网广播发现、联系人列表 | 原版自动验收通过 | 空白 GoIM 档案无需填写地址即可找到原版；关闭原版后同一联系人在运行中的 GoIM 变为离线，重新开启后恢复在线并补投。三方沙箱也自动找到两台原版。不同网卡、防火墙和办公网网段还需现场验收。 |
| 自动选择协议 | 路由回归、原版发现初验通过 | GoIM 对端用 GoIM 协议，内网通走原生连接，飞鸽／飞秋走 IPMSG。联网预览发现原版时只保留一个在线的内网通联系人；已经确认过的旧关联保留聊天身份，新的发送等待原生连接。 |
| 在线状态变化 | 原版上下线、忙碌、离开通过 | 同一联系人从在线变为离线再恢复；脚本还从原版菜单依次切换忙碌、离开、在线，GoIM 收到相同状态。 |
| 单聊文字 | 原版通过 | 沙箱验证双向中文文字，包含特殊字符。 |
| 单聊和群聊文字撤回 | 原版双向通过 | 实际逐条确认被撤回的原文消失，相邻消息保留。GoIM 可以撤回两分钟内已发出的文字，收件人需要在线。附件撤回另见文件行。 |
| 应用回执 | 原版通过 | GoIM 发给原版后，按对端和消息 ID 匹配应用回执；它不等同于已读。 |
| GoIM 获取原版头像 | 原版通过 | VMware 原版返回有效 PNG，已核对尺寸和 SHA-256。 |
| 头像更新和清除 | 双向更新、原版→GoIM 清除通过 | 原版连续缓存两张不同的 GoIM 头像，字节与样本一致。GoIM 识别原版资料里的 64 位系统头像编号，从同一联系人连续收到两张测试头像，并在原版恢复默认时清除旧头像。GoIM 清除头像后原版界面的显示尚待单独验证。 |
| 在线普通文件 | 原版通过 | 沙箱验证双向收发、中文文件名和落盘 SHA-256；每个方向用 98,321 字节的样本。 |
| 文件拒收 | 原版通过 | 原版拒收后 GoIM 报告已拒收；GoIM 拒收后原版可以重发同一个文件，重发的文件通过 SHA-256 校验。 |
| 文件撤回、取消 | 原版通过（已列场景） | 双方作为发送方都能撤回待接收的文件。原版在收文件中途取消时，GoIM 显示已取消并停止发送；原版可能保留已收的部分，沙箱确认没有完整成品。 |
| 普通文件断点续传 | 原版双向通过 | 双向均验证了从 32,768 字节继续和最终 SHA-256。GoIM 上传中断会显示失败，点击重试会沿用同一任务号和文件号；真实 TCP 中断回归验证了原邀请还能用于续传。 |
| 4 GiB 及以上单文件 | 原版→GoIM 通过 | 单文件 4,295,032,849 字节实际落盘并通过 SHA-256 校验。GoIM→原版时连接被重置，原版目标文件为 0 字节。两台原版的 Wine 对照也没有收到大文件，小文件控制有时同样失败，当前不能确定原因。GoIM 发给原版的单文件仍须小于 4 GiB。 |
| 文件夹单聊直传 | 原版双向通过 | 顶层文件、多层中文路径、空子目录和 0 字节文件均保留；逐文件 SHA-256 一致。GoIM 接收完成后才发布目录，不覆盖同名目录。单独试发完全空的根目录时，原版关闭了传输连接，因此暂不发送。 |
| 文件夹断点续传 | 原版未通过 | 原版作为发送方时，断开后未为同一邀请建立新的数据连接。原版作为接收方时保留了 32,768 字节，但重试从零接收；重传后的完整文件 SHA-256 一致。 |
| 文件夹中断后重传 | 新邀请双向通过 | 两个方向都在 32,768 字节处中断，重新接受新邀请后文件均通过 SHA-256。GoIM 发送方重试保留本地任务和消息；接收方会结束旧邀请、提示请对方重发，失败任务中仍保留选择过的目标路径。 |
| 单聊内联图片 | PNG、JPEG、GIF 原版双向通过 | GoIM 收到的三个格式与样本逐字节一致，GIF 样本有两帧；三个反向样本均从原版实际写出的缓存核对 SHA-256。 |
| 离线单聊文字和文件 | 原版双向通过 | 两个方向都让接收端实际下线。原版发出的补投文字在 GoIM 中保留原发送时间，文件通过 SHA-256。GoIM 在原版关闭时排队并重启自身；原版重新上线后，会话中出现原文，收到的文件通过 SHA-256。补投依赖两端再次同时在线。 |
| 原版创建的群聊 | 群文字、PNG／JPEG／GIF 图片原版双向通过 | 原版会话中读回 GoIM 的文字回复；双向群图与样本逐字节一致，GIF 样本含两帧。 |
| GoIM 创建和维护内网通群 | 创建、添加成员、改名、三方文字原版通过 | 选内网通联系人即可自动使用原生协议建立群。加入第二台原版后，两台原版在各自的群会话中读到对方文字，GoIM 收到两条原文；原版能打开改名后的群，GoIM 仍收到同一会话里的回复。 |
| 主动退群 | 原版双向通过 | 原版退出 GoIM 创建的三方群后，GoIM 只移除退出者。GoIM 发出的退群让原版群记录显示该成员已退出；回归验证了旧名单不会让 GoIM 重新收到群消息。 |
| 群主解散、移出成员 | GoIM→原版通过；原版→GoIM 已完成报文和状态回归 | GoIM 发出操作后原版实际关闭对应群窗口；解散保留 GoIM 本机历史。接收端只采纳该群群主的操作，旧名单和单纯改名不会恢复已移出成员的权限。 |
| 群内普通文件 | 已确认文件引用，待完成下载 | 原版把普通文件作为单独的文件引用发送到群；已见到原版发出的文件 ID、名称和大小，尚未核验下载落盘。 |
| 群主转让 | 未适配 | 此原版版本的成员菜单里未找到转让入口，未取得对应报文。 |
| 原版内置及自定义表情 | 未适配 | 独立于聊天图片；待验证内置编号和自定义资源。 |
| 原版文件共享、远程协助 | 未适配 | GoIM 的内网通握手不再宣告这些未实现的能力。远程协助属于另一个交互，需要单独定义双端授权。 |

| 建议顺序 | 工作 | 验收条件 |
| --- | --- | --- |
| 1 | 核对现场网络和客户端版本 | 在实际办公网验证自动发现和收发。如果安装版本不同，记录版本；如果有多网卡，确认选中的网段能发现原版。 |
| 2 | 补齐目录续传 | 在隔离网络中断目录传输，核对原版清单里每个文件的已收偏移和最终 SHA-256。 |
| 3 | 扩展原版群聊 | 验证群文件的实际下载及 SHA-256；确认使用中的原版版本是否提供群主转让。 |
| 4 | 扩展文件和聊天内容 | 用原版 Windows 验证 GoIM 发出的 4 GiB 以上文件；补原版表情和资料变更实测。 |

集中联调时，用户侧只需准备一台实际使用的 Windows 内网通，记下版本号，并和 GoIM 测试机连到同一办公网段。一起核对无需手输 IP 就能互相发现，以及消息和文件的基本操作。多人群基础互通、协议偏移、哈希和原版缓存由沙箱自动核对。针对 4 GiB 以上反向传输，如果 Wine 结果仍不能区分运行环境和协议差异，再用 Windows 原版作对照。

复跑命令、环境要求和报告格式见[内网通互通验证](neiwangtong-testing.md)。未适配项参考[原版更新日志](https://www.51nwt.com/rizhi.htm)和[原版文件传输说明](https://51nwt.com/help/g5.htm)。
