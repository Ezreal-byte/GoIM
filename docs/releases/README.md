# GoIM 发布规范

每个版本用 `docs/releases/<版本号>.md` 记录发布说明。以最近一次正式发布为起点，核对实际进入本版的提交和 PR。只写用户能感知或确实需要知道的变化。

按以下顺序编写各节，样式参考 [Motty v0.4.14](https://github.com/t8y2/motty/releases/tag/v0.4.14)。

| 小节 | 内容 |
| --- | --- |
| 新功能 | 本版新增的能力、适用平台和必要条件 |
| 改进 | 现有功能在体验、性能或兼容性上的变化 |
| 修复 | 发生问题的场景和修复后的表现 |
| 安装 | 用表格列出平台、架构与实际提供的包，有升级条件时在表格后说明 |
| 感谢贡献者 | 有其他贡献者的合并 PR 时，按 GitHub 账号列出贡献并链接 PR。这一节放最后 |

前三节没有对应变更时写「本版无」。构建信息放在安装之后、感谢贡献者之前。根据本版实际产物更新安装表，避免照搬旧版本的包格式。

发布时推送与源码对应的 `v<版本号>` 标签触发 [Release CI](https://github.com/Ezreal-byte/GoIM/actions/workflows/release.yml)。CI 校验各平台安装包与 `SHA256SUMS`，并为配置了签名密钥的正式版本生成签名更新源。校验成功后，以 CI 产出的 `RELEASE_NOTES.md` 为 GitHub Release 正文，随发布附上安装包、校验值和签名更新源。
